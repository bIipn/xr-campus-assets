# XRLibraries Campus — interactive systems inventory and their Unreal Engine 5 counterparts

Written 2026-10-16 from the three.js source in `/home/user/xr-campus-assets/parts/*.js` (every claim about the web build cites `file:line`). Companion to `layout.md` / `layout.json` (geometry, rooms, coordinates) and to the research notes in `../research/` (`humans.md` = MetaHuman/animation stack, `render.md` = UE 5.8 rendering, `automation.md` = editor Python / headless builds, `delivery.md` = Pixel Streaming).

**Engine target:** UE **5.8.x** (sibling research; MetaHuman Python API and MetaHuman Crowds need 5.8). Keep `CharacterMovementComponent`; Mover is still Experimental in 5.8 (`humans.md` §3.2).

**How to read the UE names in this file.** Every C++ class, component, node or function below is tagged once per section:
- `[ok]` — long-standing public UE5 API (stable since 5.0–5.4); I am confident of the spelling.
- `[verify]` — exists to my knowledge, but the exact 5.8 spelling/signature must be checked on the installed engine before code depends on it (grep `Engine/Source` or the Python stub `unreal.py`, see `automation.md` §3.0).
- `[sibling]` — taken from `humans.md`/`render.md`/`automation.md`, which carry their own verification tags.
- Nothing in this file is invented to fill a gap; §7 lists what I could not confirm.

**Units and axes.** Web numbers are metres, +Y up, camera yaw 0 looks toward −Z. Conversion to UE (from `layout.md` §1): `UE_X = 100·x`, `UE_Y = 100·z`, `UE_Z = 100·y`; `UE_yaw° = (−90 − deg(yaw)) mod 360`; `UE_pitch° = deg(pitch)`. Every "view" `{x, z, yaw, pitch}` in the JS (used by tour stops, places, stations, staff) becomes an `FXRView {Location (cm), Yaw, Pitch}` through that formula in the data exporter (§4). Speeds: ×100 (m/s → cm/s).

## 1. Cross-cutting architecture

### 1.1 Project shape
- Project `XRCampus` (`XRCampus.uproject`, `"EngineAssociation": "5.8"`), one runtime module `XRCampus` (C++) and an editor module `XRCampusEditor` (import/setup commandlets, optional). Blueprints subclass the C++ classes for art hookup; all logic in C++.
- Plugins to enable: `EnhancedInput` [ok, default], `CommonUI` [ok], `GameplayTags` [ok, built in], `Niagara` [ok], `GeometryScripting` [verify: the plugin is "Geometry Script" (`GeometryScripting`), module `GeometryScriptingCore`], `ProceduralMeshComponent` [ok, fallback], `OpenXR` + `OpenXRHandTracking` [sibling], `LevelSequence`/`MovieScene` [ok, built in], `Water` [ok, plugin name "Water"], `ControlRig` + `IKRig` + `PBIK` [sibling], `MetaHuman*` [sibling], `PythonScriptPlugin` + `EditorScriptingUtilities` [sibling], `AnimationBudgetAllocator` [sibling], `PoseSearch` (GASP motion matching) [sibling].
- Levels: persistent `L_Campus` with World Partition (or one streaming sub-level per wing mirroring `WING` = museum, waxIntro, wax, lib, school, outside, play, dive; `rides.js:277-296` is only a visibility optimisation and is replaced by streaming/HLOD). The Ocean Dive lives at the web offset `DV = {x:420, z:0}` m (`dive.js:4`) = UE (42000, 0, 0) cm, in its own data layer / sub-level loaded when the ride starts.

### 1.2 Input (Enhanced Input)
One `UInputMappingContext` per mode, pushed/popped by `AXRPlayerController` with priorities, exactly mirroring the web's mode checks (`ride.on`, `paint.on`, `STN.cur`, panels open):

| IMC (priority) | Actions (type) | Desktop (ui.js:533-563, 604-670) | Touch (ui.js:738-752) | VR (xr.js:52-68) |

| `IMC_Walk` (0) | `IA_Move` (Axis2D), `IA_Turn` (Axis1D), `IA_LookDrag` (bool), `IA_Look` (Axis2D), `IA_Sprint` (bool), `IA_Jump`, `IA_Tap`, `IA_KickHold` (bool), `IA_Undo` | W/A/S/D + arrows move, Q/E + ←/→ turn 1.7 rad/s (nav.js:238-240), Shift sprint, Space jump, LMB drag = look (0.0042 rad/px), click = tap, F = kick hold, Ctrl+Z | `UTouchInterface` stick (JOY), drag look 0.0058 rad/px, tap, Jump button, Kick button (hold) | left stick = `IA_Move` (walk direction = HMD yaw), right stick = `IA_SnapTurn` (30°, hysteresis 0.7/0.3), trigger = `IA_Tap` |

Keep the web's **drag-to-look** (mouse not captured; a click without 7 px of movement within 650 ms is a tap, ui.js:620, 666). Expose `bMouseLookRequiresDrag` so PC players can switch to captured mouse-look.

### 1.3 UI
- CommonUI: a root `UCommonActivatableWidgetStack` per layer (HUD, panels, modals) in `UXRUiSubsystem` (`ULocalPlayerSubsystem`). The web's "opening X closes Y" chains (e.g. `openStation` → ui.js/stations.js:14-17; `startPaint` ui.js:469-470; `openRide` rides.js:30) become one rule: panels are exclusive within a layer; the HUD layer stays.
- Set `GameViewportClientClass` to `CommonGameViewportClient` [ok] for CommonUI input routing.
- Text-heavy panels (catalog card, reader, station panel, blueprint viewer, chat) use `URichTextBlock` [ok] with a style DataTable. Charts/readouts the web draws on `<canvas>` (`lab.js:7-37`) become `UCanvasRenderTarget2D` [ok] textures drawn with `UCanvas::K2_DrawLine/K2_DrawText/K2_DrawBox` [ok], shown in UMG via `UImage` or on meshes via a dynamic material.
- All painted art the web generates at load (exhibit art, book covers, signs, blueprint boards, wax backdrops/rails/headers, badge icons, paint-tool icons, scoreboard, code monitors, tool labels) is **pre-rendered to PNG** by extending `unreal/Pipeline/web/export_campus.py` (it already dumps `art/<exhibit>.png` and tags meshes `item__/staff__/ride__/token__/station__/book__/bp__`, see its lines 14-19 and 124-126) and imported as `UTexture2D`.

### 1.4 Data
Every JS table becomes a `UDataTable` (row struct `FTableRowBase`) or a `UPrimaryDataAsset`, exported to JSON by a Node script (§4) and imported with `unreal.DataTableFunctionLibrary.fill_data_table_from_json_string` [sibling: automation.md §3]. IDs stay the web's string ids (`FName`), rooms/wings become `FGameplayTag`s (`Room.Lobby`, `Room.G1` … `Room.Yard`, `Wing.Museum` …).

### 1.5 Save
One `UXRProgressSaveGame : USaveGame` [ok] in slot `"xr-campus-progress"` (web key `xr-campus-progress-v1`, progress.js:4) and one `UXRPaintSaveGame` for strokes (web key `xr-campus-paint-v1`, paint.js:16); `UGameplayStatics::SaveGameToSlot/LoadGameFromSlot/AsyncSaveGameToSlot` [ok].

## 2. The systems

Each entry: **Experience · Inputs · State · Data · UE implementation · Size · Notes.**

### A. App shell, intro, attract, graphics, loop (ui.js:21-49, 754-860; gfx.js)
- **Experience.** Intro card (title, meta line "3 galleries · 15 exhibits · 12 scenes · 14 books · 4 workshops · 3 rides · 4 staff" ui.js:850, Enter / Start the tour / Browse, graphics segment High/Medium/Low, sources list). While the card is up the camera sways (`cam.yaw = sin(t·0.22)·0.32`, ui.js:778). A hint line fades after 9 s. "About" reopens the card. Reduced-motion users get instant moves (`REDUCED`).
- **State.** `entered`, `introOpen`, `attract`, `GFX.tier` (persisted; eased down after a crash, gfx.js).
- **UE.** `AXRCampusGameMode` spawns `UXRIntroWidget` (CommonUI modal). Attract = yaw oscillation in `AXRPlayerController` while the modal is open. Graphics = `UGameUserSettings::SetOverallScalabilityLevel` [ok] + the `render.md` scalability groups; "crash → ease" = check a `bCleanExit` flag in the save on start. Reduced motion = a `UXRSettings` bool consumed by rides/bob/G-forces. The web's wake/sleep render loop (ui.js:769-802) has no equivalent; UE ticks every frame.
- **Size S.**

### B. Movement and navigation (nav.js; ui.js:533-563, 598-602, 738-752; xr.js)
- **Experience.** Smooth-start/stop walking, sprint, hop with landing dip and head-bob; drag to look; **click/tap the floor to walk there** along an A* path on a 0.25 m grid (`NAV`, nav.js:77-151) with string-pulling, wall padding 0.45 m (`M_WALL`), no-go rectangles (coaster ground, wax stages, intro wall, nav.js:23-25) and obstacle circles (`OBST`); clicking a wall walks you to 1.1 m in front of it (ui.js:599-602). Keyboard/stick input cancels the path. Programmatic `goView({x,z,yaw,pitch})` walks you somewhere and turns you to face a view, turning toward the travel direction on the way when the trip is > 4 m (`travelFace`, nav.js:200, 221).
- **Inputs.** See §1.2.
- **State.** `cam {x,z,yaw,pitch}`, `PLAYER {vx,vz,y,vy,ground,jump,sprint,bob,dip…}`, `path[]`, `faceYaw/facePitch`, `JOY`, `CAMX` (extra camera offset used by the kick and the station hands).
- **Data.** `ROOMS`, `DOORS`, `NOGO`, `OBST` (nav.js:5-66). The layout spec already transcribes these.
- **UE.** `AXRPlayerCharacter : ACharacter` with `UCharacterMovementComponent` [ok]; `UCameraComponent` [ok] at the head socket; `WalkTo(Dest, FaceView)` calls `UAIBlueprintHelperLibrary::SimpleMoveToLocation(Controller, Dest)` [ok, AIModule; what the TopDown template uses] which attaches a `UPathFollowingComponent` [ok] to the player controller; `UPathFollowingComponent::OnRequestFinished` [ok] fires arrival. NavMesh: `ANavMeshBoundsVolume` [ok] over the campus, `RecastNavMesh` agent radius 45 cm (= `M_WALL`), cell size 25 cm; `ANavModifierVolume` with `UNavArea_Null` [ok] for the `NOGO` rects; furniture gets simple collision so Recast carves it (`OBST`). "Walk to 1.1 m in front of a wall": trace hit on a `Blocker` → `UNavigationSystemV1::ProjectPointToNavigation` [ok] of `Hit.Location + Hit.Normal·110`. Face-on-arrival: PlayerController interpolates `ControlRotation` toward the stored yaw/pitch with the web's `1−exp(−4.5·dt)` easing (nav.js:224, 228). Head-bob/dip: camera relative offset in Tick (port nav.js:168-189); `ACharacter::Landed` [ok] seeds the dip impulse `−min(0.8, hit·0.1)`.
- **Size M.** VR variant in §V.

### C. Picking and hover (ui.js:565-670)
- **Experience.** Mouse hover shows a label ("Open · title", "Read · title", "Use · Sieve analysis", "Hold to power up · Soccer ball", …, ui.js:635-653) at the cursor; tap dispatches on `userData` kind in this priority: token → (riding: creature fact) → ride sign → prop (ball/block) → keeper → swing → spinner → staff → easel → station/hotspot → blueprint board (with uv → part) → handbook monitor → exhibit → book → shelf end → floor (walk) → blocker (walk near).
- **UE.** Custom trace channel `ECC_GameTraceChannel1` named `Interact` (DefaultEngine.ini `+DefaultChannelResponses=(Channel=ECC_GameTraceChannel1,DefaultResponse=ECR_Ignore,bTraceType=True,bStaticObject=False,Name="Interact")` [ok]). `UXRInteractionComponent` on the PlayerController does `GetHitResultUnderCursorByChannel` [ok] (mouse) / `GetHitResultUnderFingerByChannel` [ok] (touch) / a trace from the motion controller (VR); the hit actor implements `IXRInteractable` (§3.5). Floor and walls answer the `Walkable`/`Blocker` cases through two trivial interactable actors (`AXRFloorActor`, or simply: if the hit component has the `Walkable` object tag → WalkTo). Hover label = `UXRHudWidget::SetHoverLabel`. Invisible oversized pick proxies (balls `max(0.36, r+0.12)` m sphere phys.js:69; figures box 0.55×h×0.4 humans.js:205) become extra `USphereComponent`/`UBoxComponent` with collision only on `Interact`.
- **Size S.**

### S. Soccer (soccer.js, socplay.js, socpose.js)

## 5. Build order

**Phase 0 — first playable (walk, read, learn; ~3–4 weeks of engineering, placeholder art).** Project skeleton + plugins + ini (per `render.md`) → data export + DataTables → `AXRPlayerController/Character` + Enhanced Input (desktop + touch) + NavMesh/click-to-walk → `UXRInteractionComponent`/`IXRInteractable` → rooms/HUD/minimap/toasts → exhibits + catalog card → books + reader → tour → search → progress (badges, tokens, save) → staff NPCs with preset dialogue (placeholder meshes, talk/look-at) → station framework + diorama + pendulum → ride cards/HUD + Sky Drop → wing streaming. Exit criterion: the whole tour can be played end to end without MetaHumans.
**Phase 1 — the fun stuff mechanically.** Coaster (spline/track/G-forces) → yard physics (balls, tower, swings, spinner, confetti) → soccer ball + kick (no keeper) + MetaSounds SFX → Wax Hall mechanics (`AXRWaxStageActor` with 1–2 placeholder sequences, captions, historian badge) → sieve/titration/bench stations without hands (timelines) → Ocean Dive ride logic with a greybox reef.
**Phase 2 — people and looks.** MetaHuman staff + head-tracking + blink + baked answer-bank lip-sync; keeper NPC; first-person body (shadow + arms) and kick run-up; blueprint boards/viewer; paint studio; VR mode (OpenXR, world-space UI); dive environment (fog, caustics, boids, Niagara); G-force/camera polish.
**Phase 3 — depth.** `UXRHandsClipPlayer` + FBIK hands at the five benches; the 12 authored wax scenes (MetaHuman reenactors, baked clips, carried props, effects); LLM dialogue with streaming; VR hand tracking/grabs; Pixel Streaming deployment (`delivery.md`).

# Delivering a photoreal UE5 "Walk the Archive / XRLibraries Campus" to the public — research report

Date of research: 2026-10-16. Scope: how an Unreal Engine 5 experience reaches people when the current product is a three.js website on Vercel. Everything below was checked against sources reachable from this container (Epic's GitHub repos directly; everything else via search-engine excerpts of the primary pages, because dev.epicgames.com, unrealengine.com, vendor sites and aws.amazon.com are not fetchable from here). Where a fact could not be confirmed it is marked **UNCONFIRMED**. No cvar, ini key, launch flag, npm package or C++ class is named below unless it appeared verbatim in an Epic-authored source.

---

## 0. Engine version context (affects every section)

- **Current engine: UE 5.8**, released at State of Unreal, Chicago, 17 June 2026. Headline: Lumen Lite (lighter dynamic GI), MegaLights production-ready, Mesh Terrain (experimental), Unreal MCP server plugin. Multiple outlets describe 5.8 as the last major 5.x release before UE6, with UE6 previews expected "late 2027-ish". [gamefromscratch], [80.lv], [wnhub]
- **Pixel Streaming infrastructure branches (Epic repo, read directly):** `UE5.8` = Current, `UE5.7` = Supported, `UE5.6` = End of life, `UE5.5` = Unsupported. "There are breaking changes between UE versions - so make sure you get the right version." [EpicGamesExt/PixelStreamingInfrastructure README]
- Practical consequence: author the project for **5.8** and use the `UE5.8` infrastructure branch. If Cowork's machine ends up on 5.7 (Epic's release of record Nov 2025), use the `UE5.7` branch; nothing older.

## 1. Pixel Streaming 2 (PS2) — status, architecture, embedding, cost

### 1.1 Status
- PS2 shipped as **Experimental in UE 5.5** because Epic introduced an internal WebRTC abstraction layer ("EpicRtc") and the original plugin, which used WebRTC directly, had to be rewritten. Both plugins ship together "for the time being" so teams can migrate. [Epic migration guide, read directly]
- **UE 5.8 release notes** (search excerpt of the official page) list for Pixel Streaming 2: "Add: Support for iOS and Android" and "Add: Ability to access VideoConsumer in BP and retrieve FTextureResource* in C++". Unreal Engine Remote (the mobile preview app) now uses PS2 as its streaming backend. That is a strong signal PS2 is the primary, maintained path. [UE 5.8 release notes]
- **UNCONFIRMED:** whether 5.8 still ships the original `PixelStreaming` plugin, and whether Epic has formally labelled PS2 "production-ready". The migration guide gives no removal date. Eagle 3D's (third-party) compatibility table lists PS2 as supported on 5.7+ for its platform.
- Encoder requirement (Epic Pixel Streaming reference): the streaming machine needs **NVIDIA NVENC, AMD AMF, or Apple VideoToolbox** hardware encoding; "No compatible GPU found" means the GPU lacks one. Epic recommends **AV1** where hardware supports it ("higher quality video at lower bitrates"). The reference page also contradicts itself about macOS ("supports Windows, Linux, and Mac" vs "OSX is not supported") — **treat Mac as a streamer host as UNCONFIRMED**; plan on Windows or Linux with an NVIDIA GPU.

### 1.2 Architecture (from Epic's repo, `UE5.8` branch, read directly)
Four moving parts, plus your website:

1. **The UE application** (packaged Windows/Linux build) with the PixelStreaming2 plugin. Required connection setting: `-PixelStreamingSignallingURL=ws://<signalling-host>:8888` (`-PixelStreamingIP`, `-PixelStreamingPort`, `-PixelStreamingURL` are deprecated). Other confirmed PS2 flags: `-PixelStreamingID` (streamer id), `-PixelStreamingEncoderMinQuality` / `-PixelStreamingEncoderMaxQuality` (0–100 scale, replaces MinQP/MaxQP), `-PixelStreamingEncoderQualityPreset`, `-PixelStreamingEncoderLatencyMode`, `-PixelStreamingEncoderEnableSimulcast`, `-PixelStreamingEncoderScalabilityMode`, `-PixelStreamingEncoderKeyframeInterval` (default -1 = only on request), `-PixelStreamingWebRTCMaxBitrate` (default dropped 100 → 40 Mb/s), `-PixelStreamingUseMediaCapture` (default true; ~10% more CPU on g4dn in Epic's test), `-PixelStreamingSignalingKeepAliveInterval`, `-AllowPixelStreamingCommands` (enables browser-sent console commands — leave OFF in public). Settings priority: ini < command line < console. All settings/defaults are listed under **Project Settings > Plugins > PixelStreaming2**. [migration guide]
2. **Signalling/web server "Wilbur"** (`SignallingWebServer/`, Node/TypeScript; replaces "Cirrus" of UE 5.4 and earlier). Serves the player page and brokers WebRTC offers/answers. Confirmed flags: `--streamer_port` (8888), `--player_port` (80), `--sfu_port` (8889), `--https_port` (443), `--https`, `--https_redirect`, `--ssl_key_path`, `--ssl_cert_path`, `--serve`, `--http_root`, `--homepage` (player.html), `--config_file`, `--max_players`, `--player_keepalive_timeout` (30000 ms), `--rest_api`, `--turn_secret`, `--turn_secret_file`, `--turn_ttl` (86400), `--peer_options`. Start: `npm start -- [args]` or `node dist/index.js`; Windows helper `SignallingWebServer\platform_scripts\cmd\start.bat --dev`. [Wilbur README]
3. **STUN/TURN.** Epic's hosting guide: a TURN server relays media when direct P2P fails; "if you need to support mobile devices over wireless carrier networks or clients on secured enterprise networks, you may have no choice but to use a TURN server." Epic removed the STUN/TURN reference servers it used to ship "because they were not production-grade"; `SignallingWebServer/platform_scripts/` contains scripts to run **coturn** on Windows/Linux/Mac. Security guidelines (read directly) say to use `--turn_secret` with coturn's `use-auth-secret` mode (time-limited per-peer credentials), to issue per-connection credentials via `peerOptionsProvider`, and to **route all media through TURN** so the UE box never needs a public IP. [hosting guide excerpt; Security-Guidelines.md]
4. **SFU (optional)** — `SFU/`, built on **mediasoup**: "a mechanism to allow distributing a single stream out to a large number of peers" without re-encoding, using simulcast layers. PS2 **removed "stream sharing"** (one encode to many peers); per-peer encoding is the new default and the SFU is the replacement for one-to-many. SFU `config.js` keys: `signallingURL` (default `http://localhost:8889`), `rtcMinPort`/`rtcMaxPort` (40000–49999). Docker example in README: `ghcr.io/epicgames/pixel-streaming-sfu` (needs `--network=host`). Unofficial images also on Docker Hub `pixelstreamingunofficial/pixel-streaming-signalling-server` and `.../pixel-streaming-sfu`. [SFU README; repo README]

Security notes that matter for a public site (Security-Guidelines.md): the signalling server **ships with no authentication** — add it via the `verifyClient` hook on `streamerWsOptions` / `playerWsOptions` / `sfuWsOptions` and use `authorizeStreamerId` to stop id-squatting; never expose the streamer port to the internet; keep the UE instance on a private IP; don't store secrets in the UE container.

### 1.3 Embedding the stream in the existing Vercel site
- **Vercel cannot host the signalling server.** Vercel Functions terminate after responding; Vercel staff and Ably both state WebSockets are not supported (Fluid Compute doesn't change that). [Vercel community; Ably] The Vercel site can host only the *player page/JS*; Wilbur + coturn (+ UE) must run on a VM/container host (any VPS for signalling+TURN, a GPU box for UE).
- **Frontend library (npm, MIT, published by Epic under `@epicgames-ps`, labelled "unofficial" in the README):** version-suffixed packages exist for 5.6/5.7/5.8: `lib-pixelstreamingfrontend-ue5.8` (core: WebRTC, settings, input, no UI), `lib-pixelstreamingfrontend-ui-ue5.8` (reference UI), `lib-pixelstreamingsignalling-ue5.8`, `lib-pixelstreamingcommon-ue5.8`. ES-module + CommonJS + types; "does not contain a minified/bundled output" (bring your own bundler, e.g. the Vercel/Next build). [repo README; Frontend README]
- **Minimal custom page (Epic's own example, versions are the doc's 5.2 — substitute `-ue5.8`):**
  ```ts
  import { Config, PixelStreaming } from '@epicgames-ps/lib-pixelstreamingfrontend-ue5.2';
  import { Application, UIElementCreationMode } from '@epicgames-ps/lib-pixelstreamingfrontend-ui-ue5.2';
  const stream = new PixelStreaming(new Config({ useUrlParams: true }));
  const application = new Application({ stream, settingsPanelConfig: { isEnabled: false, visibilityButtonConfig: { creationMode: UIElementCreationMode.Disable } } });
  // attach application.rootElement to the element that should host the viewport
  ```
  "HTML Page Requirements" says there are no required ids; you only need to append the player to an element that has real size (the sample body is `100vw × 100vh`, margin 0). The player fills 100% of its parent. [Customizing the Player Webpage.md; HTML Page Requirements.md]
- Two integration options for the Vercel site: (a) **iframe** pointing at the Wilbur-served `player.html` (simplest; keeps the stream page on the streaming host's origin); (b) **native embed** of the npm library inside the Vercel/Next bundle, pointing at `wss://signalling.yourdomain`. Option (b) is nicer (one origin, shared styling, your own loading UI) and lets your site call `emitUIInteraction` / `emitCommand` to drive the campus (teleport to Wax Hall, etc.) — the UE side receives it with the Blueprint node **Pixel Streaming Input > Bind Event to On Input Event** and parses JSON with **Pixel Streaming > Get Json String Value**. [Communicating from the Player Page to UE5.md]
- Use `--https` on Wilbur or a reverse proxy with TLS so the page on https://…vercel.app can open `wss://`.

### 1.4 Per-user GPU cost (self-hosted)
- Model: **one UE process per concurrent visitor** (Epic staff on forums: "every user gets their own stream"; the SFU only helps when many viewers watch the same session). A photoreal Nanite/Lumen campus is GPU-heavy, so plan **1 session per mid-range GPU** and treat 2–3 per GPU as an optimisation target, not a baseline. Third-party guidance ranges from "1–4 sessions per g4dn.xlarge depending on scene" to Linux-with-MPS claims of 12–15 light streams per GPU (vendor marketing, unverified).
- Reference on-demand prices (third-party aggregator snapshots dated 16 Jul 2026, Linux, us-east-1 — **verify on the AWS calculator**): `g6.xlarge` (1× NVIDIA L4, 4 vCPU, 16 GiB) ≈ **$0.80/h** (≈$587/mo always-on); `g4dn.xlarge` (1× T4) ≈ **$0.53/h**. Windows licensing adds to these (figure not confirmed). `g5.xlarge` (A10G) price not retrieved. [holori]
- Rule of thumb for budgeting a public free experience: **$0.6–1.0 per visitor-hour** self-hosted on a single L4/T4 with 1 session per GPU, before egress, TURN relay bandwidth and idle time. Idle time is the killer: an always-on GPU costs the same whether anyone is visiting, so autoscale to zero (GameLift Streams, Vagon, Arcware, Eagle all do this for you).

## 3. Packaged downloadable builds

### 3.1 Windows and Mac packaging
- **Windows (Win64, DX12, SM6)** is the only platform where the full feature set (Nanite, Lumen HWRT, MegaLights, Substrate, Nanite Foliage) is production-supported. Package a Shipping build; Linux is also supported and is the cheaper streaming host.
- **macOS:** Epic's "feature parity" tech blog and compatibility table: **Nanite on Apple Silicon M2 and later only (beta), requires Shader Model 6, which requires macOS 15+**; M1 explicitly not supported for Nanite. **Lumen software ray tracing works on M1+**, but **Lumen with Hardware Ray Tracing and MegaLights are "not currently supported" on Mac**. Editor minimums on Epic's requirements page: macOS Sonoma 14.0, Xcode 15.2 (page may predate 5.8). A third-party claim that 5.7 added HWRT Lumen on Metal conflicts with Epic's table — treat as unverified. **Recommendation:** ship Windows first; a Mac build is a later, reduced-quality (SWRT Lumen, no MegaLights) port.

### 3.2 Size expectations
- **Nanite:** keeps every source triangle by default ("nothing is trimmed by default… trim data to reduce disk size (download size)"). A secondary source quoting Epic's 5.8 Nanite Technical Details page gives **≈14.4 bytes per input triangle on average** (≈13.8 MB per 1 M triangles; worked example 1.55 M tris = 19.6 MB Nanite vs 149 MB as a 4-LOD static mesh). Verify on the page's "Data Size" section. Textures, not geometry, dominate in practice.
- **MetaHumans:** Epic's UEFN case study: "the average MetaHuman in Unreal Engine required 800 MB of disk space" (reduced to 60 MB in UEFN with texture compression and groom optimisation). Fab's MetaHuman package limit is 6 GB (ideal ~1.5 GB). Budget **0.3–0.8 GB per MetaHuman** depending on LOD/texture trimming; 20 wax-hall figures at MetaHuman quality can be 6–16 GB on their own unless you share bodies/clothing and cap textures at 4K.
- **Reference points:** City Sample needs ~90–110 GB of cache plus a similar project copy (community reports); a fan-packaged City Sample runtime was a 17 GB download.
- **Working estimate for this campus** (galleries, Wax Hall, baked Reading Room, workshop, recess yard, ~10–20 MetaHuman-class NPCs, Megascans surfaces): **15–40 GB installed** with 4K textures and untrimmed Nanite; **8–15 GB** with aggressive texture budgets, Nanite "Keep Triangle Percent" trimming and shared NPC assets. Expect a 10–25 GB download. (Estimate, not a measurement — cook early and read the packaged size.)

### 3.4 Code signing
- **Windows:** unsigned UE builds trigger SmartScreen "unknown publisher". Microsoft's **Azure Artifact Signing (formerly Trusted Signing): Basic $9.99/month, 5,000 signatures, $0.005 each beyond**; pricing "unchanged from Trusted Signing". Microsoft states a Trusted Signing signature gives "base reputation" on SmartScreen (reputation still accrues over time). Eligibility: organisations in US/Canada/EU/UK; **individual developers in the US and Canada** (one 2026 secondary source; Microsoft dropped the 3-years-in-business rule on 31 Oct 2025 per a forum guide). Alternative: OV/EV certificates from CAs (hundreds of dollars/year; not priced here).
- **macOS:** Apple Developer Program **$99/year**; Developer ID signing **and notarization are required** for Gatekeeper; UE .app bundles are known to need per-binary signing, correct entitlements and stapling (forum reports of notarized apps still being flagged when scope was wrong).

## 4. VR

- **PC VR (recommended path):** UE5's native **OpenXR plugin** is the supported API; Meta's own docs make "Epic Native OpenXR (Recommended)" the default integration mode for the Meta XR plugin and say the OpenXR plugin must be enabled. One Windows build serves: **Quest Link / Air Link** (Windows-only per Meta), **Steam Link for Quest** (free Valve app; requires a Steam-running PC on the same 5 GHz network, GTX 970+ and Windows 10+; it exposes SteamVR, which is an OpenXR runtime — verify the "active OpenXR runtime" setting in SteamVR before testing; not re-verified this session), and any SteamVR/OpenXR headset (Index, Vive, Pico via Streaming Assistant, Vision Pro via third-party clients).
- **Nanite & Lumen in XR:** Epic's "Nanite and Lumen for XR" page: **"considered experimental and are not officially supported"**, limited to **PC with the Deferred Renderer and DX12**, and **"not supported on Mobile XR hardware."** So PC VR with the full look is possible but experimental (expect to tune: instanced stereo + Lumen is heavy; aim at RTX 4070-class for 90 Hz).
- **Standalone Quest (Android): no Nanite, no Lumen — confirmed.** Meta's UE5 support announcement: Nanite is not available on Meta Quest and OpenXR is the only VR API Meta supports in UE5. Epic's mobile Lumen page: experimental Lumen exists only "for Unreal Engine 5.4 and newer on high-end Android mobile devices" using the **desktop renderer with Vulkan SM5**, not enabled by default, and not on iOS — Quest is not in that category. Nanite needs SM6, which Epic does not support on Android (Arm's 2026 "Mori" demo ran Nanite only on a **modified UE 5.5.2** on a Mali-G925 phone). A Quest-native build therefore means the **mobile forward renderer** (MSAA, baked/static lighting, mobile materials) and a separate, drastically reduced art pipeline — effectively a second project. Alternative for Quest with the full look: **stream it** (PC VR over Link/Steam Link at home; CloudXR.js in the Quest browser from a cloud GPU later).

## 5. Licence terms

### 5.1 Unreal Engine EULA (standard, free)
- **Games/interactive products:** **5% royalty on gross revenue above the first $1,000,000 USD lifetime per product**; no royalty in any calendar quarter where the product earns under $10,000; **products that earn no revenue owe nothing** ("distribute many commercial projects without paying any fees… including products that earn no revenue or fall below the royalty threshold"). Crowdfunding attributable to the product counts; publisher advances count. Rate drops to **3.5%** above $1 M if you ship on the Epic Games Store at or before other stores; **EGS-processed revenue is exempt** from the royalty calculation. Reporting is quarterly when royalties are due, payable 45 days after quarter end.
- **Non-game seat subscription (since late April 2024): $1,850 per seat per year, only for companies with > $1 M annual gross revenue that do not make games** (linear content, archviz, "immersive experiences not sold directly to individual users"). "Unreal Engine will remain free to use for students, educators, hobbyists, and companies generating less than $1 million in annual gross revenue." Update: from 27 May 2026 the subscription no longer bundles Twinmotion/RealityScan. → **A free public campus from a solo creator under $1 M revenue is free either way**, whether Epic classes it as a game or an immersive experience. If it ever crosses $1 M in a year as a non-game (e.g. institutional licensing), the seat fee applies instead of the royalty.
- A third-party tracker shows the EULA last updated **5 May 2026**; what changed **UNCONFIRMED** (search budget exhausted). Read the EULA change log before relying on specific wording.

### 5.2 Fab content licensing
- Fab's Standard licence has two price tiers publishers must offer: **Personal** (buyer has not generated more than **$100,000 USD gross commercial revenue in the last 12 months**, counted across controlled/commonly-controlled entities per the EULA) and **Professional** (above it). Publishers may price them identically. Standard-licence content may be used in your products, including free ones.
- **UNCONFIRMED this session** (not re-verified before the search budget ran out): the exact current "Unreal Engine-Only" content clause, Quixel Megascans' free-for-UE terms post-Fab, and MetaHuman licence terms for non-Epic engines. Assumption to carry into the plan: use Megascans/MetaHuman content only inside the UE project and inside products built with UE (which is this case), and read fab.com/eula before any Rocketbox-style redistribution of raw assets.
- Microsoft Rocketbox avatars (your current NPC source) carry their own MIT-style licence from the GitHub repo; they can be reused in UE.

## 6. Can UE5 build for the web? — verdict

- **No official path.** HTML5 was deprecated in 4.23 and moved out of the engine in **4.24** to a community-maintained platform extension; Epic stated there was "no plan to integrate it back into the vanilla Engine." Community forks exist only for UE 4.24/4.27. **UE5 ships no HTML5/WebGL/WebGPU target.**
- **Third-party:** Wonder Interactive's **SimplyStream** (WebAssembly + WebGPU RHI) has shown UE5 content (including Lyra) in a browser at Unreal Fest and in 2024–2026 press; a 2026 blog confirms "Unreal Engine 5.7 does not ship an official Epic WebGPU backend". **Pricing, licensing and general availability for UE 5.7/5.8 were not found** — UNCONFIRMED. Even if available, a WebGPU port cannot run Nanite (needs SM6/mesh-shader-class features), Lumen HWRT or MegaLights; it would be a different, reduced build.
- **Verdict:** for a "brand-new AAA PC game" look, the browser is reached only by **pixel streaming**. Keep the three.js site as the zero-cost universal fallback and treat UE5 as the premium tier (download + stream + VR).

## 7. Recommended delivery plan for a solo creator

### (a) Free-tier start (first public release, ~$0–20/month)
1. **Keep the Vercel three.js campus live** as the "instant" tier; add a landing section for the "UE5 edition" with a 4K trailer (OBS/Movie Render Queue) and system requirements (Win10/11, DX12 GPU with ≥8 GB VRAM, SSD, ~25 GB).
2. **Downloadable Windows build** on **itch.io** (0% share optional; request a butler size-limit increase before launch, or host the installer elsewhere and use itch for the page). Sign with **Artifact Signing ($9.99/mo)** if eligible; otherwise ship unsigned and document the SmartScreen "More info → Run anyway" step.
3. **PC VR for free:** same Windows build, `-vr`-capable via OpenXR; works with Quest Link/Air Link and Steam Link; no store needed. Label Lumen/Nanite-in-VR as experimental and ship a "Performance" scalability preset (Lumen Lite in 5.8 is the natural VR fallback).
4. **Streaming without a cloud bill:** run Wilbur + coturn on a small VPS (or even the Vercel-adjacent box of your choice; not Vercel itself) and the UE streamer on **your own gaming PC** for scheduled demos/events. Embed via the `@epicgames-ps/lib-pixelstreamingfrontend-ue5.8` library in the Vercel site behind a "Live demo" button that is only enabled when your streamer is online (Wilbur `--rest_api` exposes streamer counts). Alternative with zero ops: **Arcware Lite (€10/month + €0.15/min)** or Eagle's 7-day trial for a launch week.
5. Submit to **Epic Games Store** ($100, recoupable) once stable — it costs nothing in revenue share for a free title and waives the UE royalty if you ever charge.

### (b) Scalable (when traffic or funding arrives)
1. **Browser tier → pay-per-minute streaming:** Vagon Streams (≈$1.5–2.8 per user-hour on T4/L4) or Arcware; or **AWS GameLift Streams** with the Web SDK embedded in the Vercel page (gen6n classes from $0.16/h capacity; ultra ≈ $1.82/h), autoscaled to zero, Windows runtime for compatibility. Budget rule: at $2/user-hour, 500 visitors × 10 minutes ≈ $170; publish a visitor cap per day.
2. **Stores:** EGS + Steam ($100 each). Steam gives Cloud Play/GeForce NOW opt-in once listed.
3. **VR at scale:** PC VR via Steam; for Quest-in-browser, pilot **CloudXR 6.x** (OpenXR runtime on an NVIDIA cloud GPU, CloudXR.js client) — test the Quest 3 stereo-offset issue first. Standalone Quest only if a sponsor funds a mobile-renderer re-art.
4. **Mac:** only after Windows; Apple Silicon M2+/macOS 15 with SWRT Lumen, no MegaLights; $99/yr signing + notarization.
5. **Licensing stays free** below $1 M/yr; if the campus is licensed to institutions above that as a non-game, budget the $1,850/seat/yr subscription rather than royalties.

### Decision summary
- Browser = Pixel Streaming 2 (UE 5.8, `UE5.8` infra branch, AV1 on NVENC, TURN mandatory for mobile/corporate users, Vercel hosts only the player JS).
- Download = Windows first (itch.io now; EGS/Steam $100 each later), 10–25 GB, sign for $9.99/mo.
- VR = PC VR/OpenXR now (Link, Steam Link, SteamVR); standalone Quest cannot keep Lumen/Nanite.
- Web export = not viable for this look; keep three.js as fallback.
- Licence = free; 5% only above $1 M lifetime per product (3.5%/0% via EGS); Fab Personal tier applies under $100K.

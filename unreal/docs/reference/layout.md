# XRLibraries Campus — layout spec for the UE5 rebuild

Human notes to go with `layout.json` (machine-readable, generated by `gen_layout.py` in this folder; `plan.py` renders the ASCII plan below from it).
Every constant was transcribed from the three.js source in `/home/user/xr-campus-assets` (file:line cited). Nothing here is measured from screenshots.

Conventions: **three.js campus metres, +Y up, camera yaw 0 looks toward −Z** (that direction is "north"/up on the minimap), +X is east, +Z is south.
All `x0,x1,z0,z1` below are interior floor rectangles in those units. Every floor is at y = 0.

## 1. Coordinate conversion three.js → Unreal

| | formula | source / check |
|---|---|---|
| position | `UE_X = 100·x`, `UE_Y = 100·z`, `UE_Z = 100·y` (metres → centimetres) | chosen so imported meshes and these numbers agree, see cross-check |
| direction vector | `(dx,dy,dz) → (dx, dz, dy)` | same map, no scale |
| yaw | `UE_yaw° = (−90 − deg(yaw_three)) mod 360` | three yaw 0 (looks −Z) → UE −90° (looks −Y); three +π/2 (looks −X, west) → 180°; three −π/2 (east) → 0°; three π (south) → +90°. Derived from the forward vector `(−sin yaw, −cos yaw)` in nav.js:249 / ui.js:717 |
| pitch | `UE_pitch° = deg(pitch_three)` | positive looks up in both (three.js camera `rotation.x`, YXZ order, world.js:144; xr.js:56 `pitch = asin(forward.y)`) |
| compass | north (−z) → UE −Y, south (+z) → UE +Y, east (+x) → UE +X, west (−x) → UE −X | |

**Handedness.** three.js is right-handed; UE is left-handed. The UE basis written in three.js coordinates is X=(1,0,0), Y=(0,0,1), Z=(0,1,0); the right-handed cross product X×Y = −Z, i.e. a left-handed triple, so this map is a proper rotation+swap, not a mirror. A test cube at three (1,0,0) must land at UE (100,0,0) and one at three (0,0,1) at UE (0,100,0). If an import mirrors text on signs, fix the importer's axis settings rather than the data.

**Cross-check against the Blender note** (`docs/realism-plan.md:25`, `bl/library.py:4,29`): Blender `(bx,by,bz) = (x, −z, y)`.
- Blender → glTF with `export_yup=True` (bl/library.py:622, export_reading_room.py:74) gives glTF `(bx, bz, −by) = (x, y, z)` = three.js campus axes. This is why `lib/lib.glb` loads "already in campus coordinates" (parts/baked.js:73) and why `unreal/Pipeline/out/*.glb` are in three.js axes (manifest.json: "metres, three.js axes (y up)").
- Blender → UE via FBX (UE's Y axis is the mirror of Blender's) gives `(bx, −by, bz) = (x, z, y)` — exactly the map above.
- `unreal/Pipeline/blender/export_reading_room.py:18-20` documents the same glTF→UE map "(X=x, Y=z, Z=y) cm" for UE's glTF importer. All three routes agree. **Verify on the first import** with the test-cube rule above; I did not run Unreal here.
- The alternative "campus north = UE +X forward" map `(−z, x, y)` is also non-mirroring but is a 90° yaw of the chosen one and would not line up with meshes imported from the existing exports, so it is not used. The galleries therefore run along **−Y** in UE and the Recess Yard is at **+X**.

Sun: `SUN_DIR = [40, 62, 30]` (outdoor.js:4) is the direction *to* the sun → unit (0.502, 0.778, 0.377): elevation 51.1°, azimuth 126.9° clockwise from north (south-east). UE DirectionalLight forward = −(to-sun) mapped = (−0.502, −0.377, −0.778) → rotator **Pitch −51.1°, Yaw −143.1°, Roll 0** (check: (cos p cos y, cos p sin y, sin p) = (−0.502, −0.377, −0.778)).

## 10. Ambiguities and decisions for the UE build

1. **Two suns.** The outdoor sun (SE, 51° high) and the library bake's west sun (19° high) contradict each other. Pick the global SUN_DIR for the yard; give the Reading Room its raking light with a local (rect/spot) light outside the arched window or accept the change. The sun is off indoors on the web only to save shadow cost — in UE let it through the windows.
2. **Library room vs nav rect.** The playable library is the full −32..−12 × −13..7 shell; the stacks (x < −23 outside the aisle) are blocked in nav. UE: build the full room from `ReadingRoom.glb`, block with collision on the bookcases.
3. **School hall width.** Built −4.75..−1.25; lockers make the clear width −4.33..−1.67. The four classroom walls are coincident with the hall walls (offset 0.012 m, rooms.js:191,280,340) — model one 0.3 m wall.
4. **Wall thickness** does not exist in the web build (planes). Suggested: 0.3 m interior, 0.45 m exterior (matches the library reveal); keep interior faces on the coordinates here, grow outward.
5. **Studio windows** look at a painted backdrop at x 24.8; in UE the view is the real brick school wall of Room 102's side — consider making them clerestory or keep the backdrop as a lightbox.
6. **Exhibit viewpoint distances** depend on screen aspect (`fitDist`); the JSON uses 4.0 m (walls), 5.0 m (end wall), 2.5 m (pedestals) as representative values.
7. **Light units** are relative (see §8). Yaw values for staff/stages/exhibits in the JSON are "facing direction" yaws (`ue_yaw_note` fields explain which convention each uses).
8. Scene names are wrapped in a blurb that says the figures are reenactors, not likenesses — keep that text in UE.
9. `unreal/Pipeline/README.md` is referenced by `export_reading_room.py` but does not exist; `unreal/Pipeline/out/campus/*.glb` (three.js GLTFExporter greybox, 8 wings, tagged `item__/staff__/ride__/token__`) and `ReadingRoom.glb` already exist and are in the same three.js axes this spec uses.
10. Minimap rectangle for `lib` (−32..−12) differs from the nav rect; the minimap one is the real room.
